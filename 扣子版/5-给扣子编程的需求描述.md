# 直接粘进「扣子编程」对话框的那段话

> 新版扣子编程不让你拖节点了 —— 你跟它说清楚要什么，它生成 DAG，
> 你在右边的「预览」里看它画出来的流程图和运行结果。
>
> **这反而更接近招聘方想要的能力**：不是「会拖方块」，是「能把业务流程讲成一张能执行的图」。
>
> 用法：把下面第一个代码框**整段复制**，粘进左下角那个输入框，回车。

---

## 粘这段

```
场景：一家餐馆的微信客服分流。目标不是"答得更聪明"，而是"答不上来的时候老实转人工"。

【1. 它要做什么】
顾客发一句话 → 先去知识库检索 → 判断检索结果够不够回答问题
→ 够就用大模型按资料回答；不够就直接输出转人工话术，这条路径不调用任何大模型
→ 返回结果。

【2. 输入】
一个字符串参数 question，内容是顾客原话。

【3. 路由】
- 知识库检索节点：检索"老灶房客服"知识库，query = question，召回 4 条，相似度阈值 0.75。
- 代码节点 A：统计检索结果的条数 hit_count 和最高分 top_score，空列表和 null 都要能处理。
- 选择器 1：hit_count > 0 走"有命中"分支，否则走"转人工"分支。
- 选择器 2（接在"有命中"分支上）：top_score >= 0.75 走"回答"分支，否则走"转人工"分支。
- 大模型节点（只在"回答"分支）：系统提示词见下；用户提示词把检索到的资料全文和 question 一起给它。
- 代码节点 B（"转人工"分支）：固定返回话术，不调用任何模型。
- 两个分支都汇到结束节点。

【4. 期望输出】
answer（字符串）、need_human（布尔）、hit_count（整数）。

【5. 硬要求】
"转人工"这条路径上绝对不能有大模型节点。资料里没有的问题，模型一次都不能被调用。
这是整个设计唯一重要的地方，比回答得好不好听重要得多。

【6. 回答分支的系统提示词】
你是「老灶房·江湖菜（观音桥店）」的在线客服，在微信上回答顾客的问题。
只根据给你的资料回答，资料里没有的一律说"这个我这边不太确定，帮您转人工问一下哈～也可以直接打订座电话 023-6789 1234"。
不许推测、不许补充资料里没写的细节，价格、时间、人数、电话必须和资料完全一致。
口语化、亲切、简短，1~3 句话，像微信上打字，可以用"哈""哦""～"。
绝对不要说"根据资料""知识库""文档中显示"这类字眼。
顾客砍价、要折扣赠品，只报资料里写明的优惠，不许自己承诺。
顾客投诉、催单、要求退款，不辩解，统一回"这个我帮您转人工处理哈，稍等一下～"并给出订餐电话。
顾客问和本店无关的事，回"我主要帮您解答本店的问题哈～"。
输出纯文本，不要用任何 markdown 符号（星号、井号在微信里会显示成乱码）。

【7. 转人工分支固定话术】
这个我这边不太确定，帮您转人工问一下哈～您也可以直接打 023-6789 1234。
```

---

## 它问你细节时，用这段回

生成过程中它可能追着问「代码节点怎么写」。把这段给它：

```
代码节点 A（统计命中），输入 params["items"] 是检索结果列表，输出 hit_count / top_score：

count = 0
best = 0.0
items = params.get("items") or []
if isinstance(items, list):
    for it in items:
        if not isinstance(it, dict):
            continue
        content = it.get("content") or it.get("text") or ""
        score = it.get("score") or it.get("similarity") or 0
        if str(content).strip():
            count += 1
            try:
                best = max(best, float(score))
            except (TypeError, ValueError):
                pass

返回 {"hit_count": count, "top_score": best}


代码节点 B（转人工），不调用任何模型，只返回：

返回 {"answer": "这个我这边不太确定，帮您转人工问一下哈～您也可以直接打 023-6789 1234。",
      "need_human": True, "hit_count": params.get("hit_count", 0)}
```

## 生成出来之后，你必须自己验这四件事

它画得再漂亮也不等于对。**右边「预览」里跑这四句，一句一句看它走哪条路：**

| 输入 | 该走 | 看什么 |
|---|---|---|
| 你们几点关门？ | 回答分支 | 答出 22:30 打烊、21:45 最后点餐 |
| 有包间吗，能坐几个人？ | 回答分支 | 6 个包间、8–20 人、订金 200 |
| 你们店里有篮球场吗？ | **转人工分支** | `need_human = true`、`hit_count = 0` |
| 你们提供儿童看护吗？ | **大概率走错** | 见下 |

**第 4 条走错不是 bug。** 资料里写着「儿童套餐」「儿童餐具」，顾客问「儿童看护」，
词面撞上了，检索分够了 —— 所以它进了回答分支。
你的代码版实测过同一件事：完全无关的问题能拒掉 91.7%，但跟资料撞词的问题只有 25%。

**这条你要主动跟面试官讲，别等他问出来。** 一个能说清自己方案在哪儿失效的人，比一个说「我的准确率 100%」的人可信得多。
