# 在扣子上搭一个「工作流」—— 今晚 1~1.5 小时

> **这篇和 `3-搭建步骤.md` 不是一个东西，别看混了。**
>
> - `3-搭建步骤.md` 做的是**智能体**：把提示词 + 知识库丢进去，平台自己决定什么时候查库。
> - 这篇做的是**工作流**：每一步走哪条路、什么条件下转人工，**由你在流程图上画死**，平台不许自由发挥。
>
> 招聘方要的「工作流搭建经验」指的是后者。两者的差别就是面试时最能讲的东西：
> **智能体是「让模型自己决定」，工作流是「把不该由模型决定的部分拿回来」。**

---

## 一、今晚要做出来的东西

一条**客服分流**工作流，跑通这个过程：

```
顾客提问
   ↓
知识库检索（只查，不回答）
   ↓
数一下：命中了没？最高分够不够？
   ├─ 够   → 大模型节点，按资料用人话回答
   └─ 不够 → 代码节点，直接吐转人工话术 + 电话  ← 这一步完全不调大模型
   ↓
结束节点，返回：回答 / 是否转人工 / 命中几条
```

**这就是你代码版里那个「检索层拒答闸门」的图形化版本。** 换成低代码平台，
同一个架构决定你还能做出来 —— 这句话在面试里非常值钱，因为它证明你不是「会点一个平台的按钮」，
而是**有一个自己的方法，能换平台复现**。

## 四、七个节点（拿它当验收表，不是当施工图）

### 节点 1 · 开始

点开「开始」节点 → 添加一个输入参数：

| 参数名 | 类型 | 说明 |
|---|---|---|
| `问题` | String | 顾客说的话 |

### 节点 2 · 知识库检索

从左边节点栏拖一个 **知识库检索** 出来，连到开始节点下面。

| 设置项 | 填什么 |
|---|---|
| 知识库 | 选你建好的那个（见下方说明） |
| 查询内容 | 引用开始节点的 `问题` |
| 召回条数 | `4` |
| 相似度阈值 | `0.75`（有的版本叫「最小匹配度 / 匹配度阈值」，没有这一项就跳过，交给下一个节点判） |

**这个节点的输出是一串结果列表**（叫 `outputList` 之类），里面每条带内容 `content` 和分数 `score`。
下一步要用代码把它数出来。

> **知识库还没建？** 同样在**扣子编程**里建：资源库 → **+资源** → **知识库** → 文本数据 →
> 上传 `2-知识库.txt` → 自动分段 → 混合检索 / 阈值 0.75 / 召回 4。
> `3-搭建步骤.md` 第二步的**参数**全都有效，只有「在哪个网址点」那句作废 —— 它写的是旧版入口。

### 节点 3 · 代码节点（数命中）

拖一个 **代码** 节点，连在知识库检索后面。

- 输入参数：`列举` → 类型选 **Array\<Object\>** → 值引用上一步的输出列表
- 代码语言：**Python**
- 输出参数：`命中数`（Integer）、`最高分`（Number）

代码贴这段（**这是完整的，直接替换编辑器里原来的内容**）：

```python
async def main(args: Args) -> Output:
    params = args.params
    items = params.get("列举") or []

    # 检索没结果时平台给的可能不是空列表而是 None，两种都要接住
    if not isinstance(items, list):
        items = []

    count = 0
    best = 0.0
    for it in items:
        if not isinstance(it, dict):
            continue
        # 不同版本字段名不一样，三个都试一遍
        content = it.get("content") or it.get("text") or ""
        score = it.get("score") or it.get("similarity") or 0
        if str(content).strip():
            count += 1
            try:
                best = max(best, float(score))
            except (TypeError, ValueError):
                pass

    return {
        "命中数": count,
        "最高分": best,
    }
```

> **出错就先别改代码。** 九成的报错是输入参数的类型没选对 ——
> 必须是 Array 类型、引用上一节点的**列表**输出，不是引用整个节点。
> 报错信息里说找不到 key 的话，把 `it.get(...)` 那几行的候选字段名对着实际输出再核一遍。

### 节点 4 · 选择器（第一个分叉：有没有命中）

拖一个 **选择器 / 条件分支**，连在代码节点后面。

- 条件：`命中数` **大于** `0` → 这个分支叫「有命中」
- 设好之后，把「选择器」的**另一个出口**（否则 / 否则分支）也拖出来 ✓

### 节点 5 · 选择器（第二个分叉：分够不够）—— 在「有命中」分支上

**再拖一个选择器**，接在第一个选择器的「有命中」出口上。

- 条件：`最高分` **大于等于** `0.75`

两个出口：
- **满足** → 叫「答」
- **否则** → 叫「分太低，也转人工」

> **为什么分成两个选择器而不是一个？** 因为这个平台的单个选择器一般只判一个「是/否」，
> 想表达「A 且 B」要么嵌套、要么用条件组。**嵌套虽然丑，但一眼能看出逻辑。**
> 这是个可以说的小细节：**流程图是给人看的，能少合并就少合并。**

### 节点 6 · 大模型（「答」分支）

拖一个 **大模型** 节点，接在第二个选择器的「满足」出口。

- 模型：随便一个能用的（豆包 / DeepSeek 都行，别用最贵的）
- **系统提示词**：把 `1-人设提示词.txt` 整段粘进去
- **用户提示词**：粘这段

```
【可用的店铺资料】
{{资料}}

【顾客的问题】
{{问题}}

请只根据上面的资料回答。资料里没有的，说"这个我不太确定，帮您转人工问一下哈"。
```

- 两个变量分别引用：`资料` ← 知识库检索节点输出的内容拼接；`问题` ← 开始节点的 `问题`
- 输出参数：`回答`（String）
- **温度调低**（0.3 左右）

> `{{资料}}` 这一项如果这个版本的检索节点没法直接拼成一个字符串，
> 就在代码节点里顺手多输出一个 `资料全文` 字段（把 `content` 用 `\n` 连起来），从那儿引用。
> **这是今晚最可能卡住的地方，卡住就改成在代码节点里拼。**

### 节点 7 · 代码节点（转人工）

拖一个 **代码** 节点，让它同时接住**第一个选择器的「否则」**和**第二个选择器的「否则」**两条线。

（接不上的话就复制成两个一样的节点，分别接 —— 结果一样，别在这上面耗时间。）

- 输出参数：`回答`（String）、`是否转人工`（Boolean）

```python
async def main(args: Args) -> Output:
    phone = "023-6888 8888"   # ← 改成资料里的真电话

    return {
        "回答": f"这个我这边不太确定，帮您转人工问一下哈～您也可以直接打 {phone}。",
        "是否转人工": True,
    }
```

**看清楚这个节点里没有任何模型调用。** 这就是整套设计的意义：
资料里没有的问题，**一个 token 都不花**。

### 结束节点

把两条路都汇到 **结束** 节点，输出三个字段：

| 输出名 | 引用自 |
|---|---|
| `回答` | 大模型节点的 `回答` / 转人工节点的 `回答` |
| `是否转人工` | 转人工节点 `True`；大模型那条路直接填固定值 `False` |
| `命中数` | 代码节点的 `命中数` |

（两条路的输出名字必须一致，否则结束节点接不上 —— 这是这个平台最常见的坑。）

## 五、测试（这一节比搭建更重要）

画布右上角有**试运行 / 运行**。跑这 6 条，一条一条核对：

| 输入 `问题` | 应该走哪条路 | 期望结果 |
|---|---|---|
| 你们几点关门？ | 大模型 | 22:30 打烊、21:45 最后点餐 |
| 有包间吗，能坐几个人？ | 大模型 | 6 个包间，8–20 人，订金 200 |
| 人均多少钱？ | 大模型 | 65–80 元 |
| 停车方便吗？ | 大模型 | 负二楼，满 100 免费停 3 小时 |
| 你们店里有篮球场吗？ | **转人工** | `是否转人工 = true`、`命中数 = 0` |
| 你们提供儿童看护吗？ | **大概率走错** | 见下面 |

**前四条对了，说明知识库和提示词没问题。第五条对了，说明分流逻辑没问题。**

第六条你大概率会看到它**走进了大模型分支**——因为「儿童」两个字在资料里出现过（儿童套餐、儿童餐具）。
**这条错不是你的 bug，是这类检索的物理天花板。** 你代码版里已经量过了：完全无关的能拒掉 91.7%，
跟资料撞词的只有 25%。**面试时主动说这条，比等面试官问出来强十倍。**

## 七、卡住了怎么办

按这个顺序自查，**别一上来就怀疑平台**：

1. **节点连不上** —— 上一节点的输出类型和下一节点的输入类型对不上（最常见：要把 Array 改成引用列表而不是引用节点）
2. **代码节点报 key 不存在** —— 输入参数名和你代码里 `params.get("...")` 的名字不是同一个
3. **结束节点报「变量缺失」** —— 两条分支的输出字段名不一致
4. **检索永远返回空** —— 知识库没真正上传完 / 检索节点绑的不是那个库
5. **平台界面和我写的不一样** —— 它在改版。**按功能找节点，名字对不上不要紧**

真卡住超过 20 分钟，**先截图发我，别硬耗**。
